# 本机 Key 存储变更 · 0.2.2 build 5

按用户要求，模型和 Bark 凭据改为应用本机配置文件，普通请求不再读取或写入系统钥匙串。

- 位置：`~/Library/Application Support/TaskSecretary/local-secrets/`，不会放进 `.app`、项目工程、公开仓库或任务导出备份。
- 本地明文。目录700、文件600；在写入任何字节前即以600创建临时文件，fsync后原子替换。文件名按服务和账户哈希隔离，不允许用服务名拼接任意路径。拒绝凭据目录/文件符号链接。
- 保留模型服务来源隔离及旧配置映射，但旧映射只会查找本机文件，不会自动回退钥匙串。
- 手动迁移按钮是唯一使用Keychain API的路径：读取本项目条目，写入并回读核对后移除相应旧项；已有不同本地值不被覆盖，失败保留旧项。
- 两机各自配置Key，无自动凭据同步。提醒事项系统授权仍然必需；此改动不消除临时签名更新导致的TCC重新授权。

## 实际验证

233项测试通过，其中6项新测试直接运行生产LocalSecrets实现，检查跨进程保存/读取、权限、服务/账户隔离、原子替换、符号链接拒绝及路径隔离。测试只使用合成Key。

实际打包、严格签名校验通过。两机已安装同一0.2.2/build5，二进制SHA256均为 `65c943c3629b5af2c4e62106250641156b28e21a3ce3ca2ca24c3313120c1570`。ZIP SHA256为 `e0806913ed4e562be792cc859770eb32e167be5753ba011ec0948ecf6578bfb3`，归档文件名中无local-secrets目录。

后台迁移CLI实际报告2项不可访问、0项保存、0项移除；没有将此记为迁移通过。随后从真实App设置触发迁移，用户允许后，UI实际回执为“已迁移2项Key，移除2项旧钥匙串条目”。本地目录700、2个文件均600，值均非空（没有输出值）；查询旧cloud/Bark条目均返回44（不存在）。

实际App经本地Key成功请求云模型，创建 `POC_DUAL_20261026_LOCALKEY`（mini任务19，book任务12）；随后已移入mini可恢复回收站，book查询确认不再存在。App中Bark测试实际返回“Bark API已接受”，没有把API接受当作手机本次真实送达。独立进程从本地文件读取Key发送合成云请求，HTTP200并返回预期固定文本。

用户最终允许mini提醒事项后，再次重启完全相同的构建；AX实际显示提醒事项已连接、活动5/完成5、微信恢复连接；无需再做提醒事项授权操作。book新构建查询也恢复5项活动。没有复制Key到book，两个设备分别配置。

原双机验证结论另见 `DUAL_MAC_20261026.md`：基础同步通过子项，跨机扩展数据缺失和编号不一致仍未修复；本轮Key存储变更不宣称修复双机模式。

## 0.2.4 产品入口清理

用户明确目前只有本人安装，不需要把一次性旧Key迁移做成产品功能。已删除迁移按钮、提示、TaskService方法、LegacyKeyMigration实现及两个迁移脚本；使用指南同步清理。既有本机Key文件逐文件摘要比较保持不变。构建、打包与严格签名检查通过，最终App无SecItem读写API引用。两台已安装0.2.4/build7，用户处理本次提醒事项授权后，两端实际查询均恢复5项待办、76条日志，格式化输出哈希相同。没有为删除入口重复编写或重跑不相关测试。历史迁移结果仍保留作为证据。
